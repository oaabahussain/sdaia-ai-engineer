## Single-track coupling inventory

- `src/config.js`: exports `ACTIVE_TRACK_ID='sdaia-ai-engineer'`.
- `src/storage/browser.js`: imports `ACTIVE_TRACK_ID` and calls `loadRuntimeBundle(loadJson, ACTIVE_TRACK_ID)`.
- `scripts/contract_test.js`: imports `ACTIVE_TRACK_ID` and loads the current manifest through it.
- `server/app/main.py`: `DEFAULT_TRACK_ID = os.getenv('TRACK_ID', 'sdaia-ai-engineer')`; `GET /v1/bank` loads that default.
- `scripts/verify_live_release.js`: fetches `tracks/sdaia-ai-engineer/manifest.json` directly.
- `.github/workflows/ci.yml` and `.github/workflows/pages.yml`: explicitly assert `_site/tracks/sdaia-ai-engineer/presentation.json`.
- `sw.js` / `scripts/verify_sw_assets.js`: shell verification is manifest-based but has no registry bootstrap contract yet.
- `StateV2`: already namespaces learner data under `tracks[trackId]`; `preferences` is closed to `lang` and `theme`.
- `RuntimeBundleV2`: already describes one selected track at a time and accepts explicit track ID in browser runtime loader.
